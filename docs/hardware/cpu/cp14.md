# CP14 register transfers

CupidGBA models the GBA's disabled debug communications channel through ARM
MRC and MCR instructions addressed to coprocessor 14. A read returns the word
already fetched at the instruction address plus eight. Selector fields do not
select separate debug-register storage. A write discards its value.

A register read consumes a coprocessor transfer clock and an internal load
clock after the opcode fetch. A write consumes the transfer clock only.
These phases make no additional memory request. They advance peripheral time
and mark the following opcode request nonsequential; a populated cartridge
prefetch queue can still supply it. A failed ARM predicate consumes only its
ordinary fetch. This follows the ready-transfer sequences in sections 6.16
and 6.17 of the [ARM7TDMI technical reference manual](https://documentation-service.arm.com/static/5e8e1323fd977155116a3129).

When an MRC destination is r15, bits 31 through 28 of that fetched word replace
NZCV. Other CPSR bits, the active bank, the IRQ-mask sample and the sequential
PC remain intact. Predicates gate both reads and writes before any register or
flag effect. Coprocessor numbers 0 through 13 and 15 retain undefined-instruction
handling, as do the unsupported memory-transfer and data-processing classes.

Seven `arm.cp14-*` groups execute owned instruction streams. They cover all
16,384 read/write selectors across BIOS, EWRAM, IWRAM and six ROM windows;
every destination; all old/new flag combinations; privilege banks and masks;
all ARM predicates; and exception entry/return controls. A synthetic 32 MiB
image supplies executable bytes in both halves of each ROM window.

DMA cases replace a future RAM opcode before the CPU completes its fetch.
The CP14 result follows that completed fetch while timer progress agrees with
elapsed bus clocks, including clock wrap. These checks cover functional bus
integration. External debugging hardware and physical coprocessor-interface
busy handshaking remain outside this disabled-channel model.

The timing matrix adds 576 scenes across both transfer directions, r0/r15,
executed and failed predicates, nine execution windows, cartridge prefetch
settings and four clock epochs. It requires exact elapsed clocks, timer
progress, the next request type, retained pipeline words and register/status
state. The preceding core fails this matrix.

The checksum-pinned original cartridge now passes its 75h timer comparison,
both live read-value comparisons and the N-flag guard through both BIOS paths.
The preceding core reads 73h at that unchanged timing comparison. All four
observations must issue in order, followed by the original pre-display result
and completed terminal. Input bytes, expected values and execution guards
remain unchanged. The original cartridge does not measure MCR timing; its
write duration is checked against the processor sequence by the native matrix.

Enable the optional cartridge with `CUPID_CP14_PROBE_DIR`, pointing to a root
containing `arm/Coprocessor_14.gba`. `tests/roms/check_cp14_probe.py --fetch`
downloads the pinned image and its license notice into the chosen directory.
`CUPID_TEST_BIOS` adds its external-firmware run. Linux and Windows CI run the
built-in-firmware case.
